Method

The sample was assembled from Open Brewery DB public listing pages, using the page snippets visible in search results as the evidence source. The docs page confirms the API fields and the type vocabulary used here.

Type Comparison

micro 2 Both records show street-level addresses and conventional visitor locations. Strong directory utility; fields are complete enough for cards and maps.
brewpub 2 Both records are visitor-facing and include street addresses in the listing snippet. High usefulness for end users; good fit for static directory cards.
planning 2 Both records omit street lines in the visible listing snippet and only expose city/state/postal context. Lowest completeness in this sample; should be clearly flagged as not yet open.
proprietor 2 Both records have street addresses, but the type indicates an incubator/contract-style operation rather than a standard visitor brewery. Useful for operational coverage, but not equivalent to a public taproom listing.

Source-Quality Summary

  • Completeness: planning records were the least complete in the visible snippets because the street field was absent.
  • Visitor relevance: micro and brewpub entries are the strongest candidates for public directory cards.
  • Semantics: proprietor records are location-rich but should not be counted as equivalent to visitor-facing breweries.
  • Coverage: this is a narrow sample, so it is suitable for qualitative comparison, not dataset-wide inference.

Caveats

  • The sample is page-filtered and intentionally small; it is not representative of the full Open Brewery DB corpus.
  • The evidence comes from listing-page snippets, so fields such as coordinates, phone, and website were not used here.
  • The docs page and listing pages are public read-only sources; no write APIs were used.
